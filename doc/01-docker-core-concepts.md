# 第一部分：建立 Docker 的核心认知

## 1. Docker 解决什么问题

Docker 可以把程序和它需要的运行环境打包成镜像，再根据镜像创建容器来运行程序。

以 C++ 开发为例：把 `g++`、`cmake` 和依赖库准备在镜像中，用容器执行编译；源码通过绑定挂载保存在宿主机上。

## 2. 五个核心概念

| 概念 | 含义 |
|---|---|
| Image（镜像） | 创建容器的只读模板，包含文件和运行配置 |
| Container（容器） | 根据镜像创建的实例，有自己的可写层，可以启动、停止和删除 |
| Dockerfile | 描述如何构建镜像的文本文件 |
| Volume（数据卷） | 由 Docker 管理、独立于容器生命周期的存储 |
| Port Mapping（端口映射） | 将宿主机端口收到的请求转发到容器中的服务端口 |

核心关系：

```text
Dockerfile ──构建──→ 镜像 ──创建并启动──→ 容器
  说明书             模板                 实例
```

Linux 容器共享运行它们的 Linux 内核，不会各自启动一个内核。Ubuntu 镜像包含 Ubuntu 的用户空间文件，不等于一台完整的 Ubuntu 虚拟机。

## 3. 镜像与容器：模板和实例

同一个镜像可以创建多个容器。默认情况下，每个容器的文件修改相互独立，也不会修改原镜像。

假设原镜像只有 `g++`，用它创建容器 A 和 B，然后只在 A 中安装 `cmake`，且没有使用共享挂载：

| 操作或对象 | 是否有后来安装的 cmake |
|---|---|
| 原镜像 | 没有，容器内的修改不会自动写回镜像 |
| 容器 B | 没有，A 的修改不会自动同步到 B |
| 停止 A，再启动同一个 A | 有，A 的可写层仍然保留 |
| 删除 A，再用原镜像创建新容器 | 没有，A 的可写层已被删除 |

```text
原镜像：包含 g++
    │
    └── 容器 A
         └── 可写层：后来安装的 cmake
              ├── 停止再启动 A → 保留
              └── 删除 A       → 删除
```

**停止容器不等于删除容器。** 容器的可写层可以跨越停止和启动，但不能跨越删除和重建。

如果希望以后创建的容器都自带 `g++` 和 `cmake`，应将安装步骤写进 Dockerfile，构建新镜像，再用新镜像创建容器。

## 4. 数据保存：Volume 与绑定挂载

需要长期保存的数据，应放在数据卷或宿主机目录中。

| 方式 | 数据位置 | 常见用途 |
|---|---|---|
| Volume（数据卷） | Docker 管理的存储位置 | 数据库数据等 |
| Bind mount（绑定挂载） | 你指定的宿主机目录 | 项目源码、配置文件 |

指南中的 `-v $(pwd)/test_data:/data` 属于绑定挂载。

### 绑定挂载不是复制文件

```text
宿主机                         容器
~/cpp-demo/ ──绑定挂载──→ /workspace/
  └── main.cpp                  使用 g++ 编译
```

这里两条路径访问的是同一份文件：

- 宿主机修改文件，容器中能看到变化。
- 容器修改文件，宿主机上的对应文件也会变化。
- 删除容器，宿主机上的文件仍然保留。
- 在容器内主动删除挂载目录中的文件，也会删除宿主机上的对应文件。因此，绑定挂载不是备份。

### 练习结论

将宿主机的 `~/cpp-demo` 绑定挂载到容器的 `/workspace`，然后在容器中创建两个文件：

| 文件 | 删除容器后的结果 | 原因 |
|---|---|---|
| `/workspace/hello.cpp` | 保留 | 实际保存在宿主机的挂载目录中 |
| `/tmp/notes.txt` | 删除 | 假设 `/tmp` 未挂载，文件只保存在容器可写层中 |

数据卷同样可以在容器删除后保留数据，前提是没有另外删除数据卷。

## 5. 端口映射：从宿主机访问容器服务

默认情况下，容器有自己的网络环境。服务监听容器的 `80` 端口，不代表它也在宿主机的 `80` 端口提供服务。

端口映射的写法：

```bash
-p 8080:80
#  宿主机端口:容器端口
```

访问路径：

```text
宿主机浏览器访问 http://localhost:8080
                  ↓
           宿主机端口 8080
                  ↓
             容器端口 80
                  ↓
                Web 服务
```

端口映射不会改变程序监听的端口。服务仍监听容器内的 `80`，Docker 负责转发。

如果容器仅用于编译 C++，没有需要从外部访问的网络服务，通常不需要端口映射。

### 两个容器能否使用相同端口？

在各自独立的默认网络环境中，两个容器都可以监听自己的 `80` 端口：

| 容器 | 映射参数 | 在宿主机浏览器中的访问地址 |
|---|---|---|
| A | `-p 8080:80` | `http://localhost:8080` |
| B | `-p 8081:80` | `http://localhost:8081` |

它们不会冲突：容器端口属于各自的网络环境，宿主机端口也不同。这里的 `localhost` 指运行浏览器的本机。

## 6. 串起 C++ 开发场景

```text
Dockerfile：写明安装 g++、cmake
    ↓ 构建
镜像：包含开发工具的环境模板
    ↓ 创建并启动
容器：运行编译命令
    ↑ 绑定挂载
宿主机源码目录：保存和编辑代码
```

本节要记住：

1. 镜像是模板，容器是实例。
2. 修改容器不会自动修改镜像。
3. 停止容器保留可写层，删除容器会删除可写层。
4. 重要数据通过数据卷或绑定挂载保存在容器可写层之外。
5. 端口映射顺序是“宿主机端口:容器端口”。
