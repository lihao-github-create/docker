# 第一部分：建立 Docker 的核心认知

本节对应 [学习指南](../learn_guide.md) 的第一部分。先理解三个问题：运行环境如何准备、容器删除后数据是否保留、宿主机如何访问容器服务。具体操作在后续章节中练习。

## 1. Docker 解决什么问题

C++ 项目换一台机器后，往往需要重新安装编译器、构建工具和依赖库。Docker 可以将这些环境准备步骤写进 Dockerfile，构建为镜像，再用镜像创建容器执行编译或运行程序。

在本仓库的 C++ 开发场景中：**工具放在镜像里，编译在容器中执行，源码保存在宿主机上。** 容器通过绑定挂载访问源码，不必把编辑器也装进容器。

## 2. 五个核心概念

| 概念 | 含义 | 在开发中负责什么 |
|---|---|---|
| Dockerfile | 描述如何构建镜像的文本文件 | 记录工具和依赖的安装步骤 |
| Image（镜像） | 创建容器的只读模板，包含文件和运行配置 | 提供准备好的环境 |
| Container（容器） | 根据镜像创建的实例，有自己的可写层 | 执行编译命令或运行服务 |
| Volume（数据卷） | 由 Docker 管理、可独立于容器保存的存储 | 保存数据库等应用数据 |
| Port Mapping（端口映射） | 将宿主机端口收到的流量转发到容器端口 | 通过宿主机端口访问容器服务 |

核心关系：

```text
Dockerfile ──docker build──→ 镜像 ──docker run──→ 新容器
  构建步骤                   环境模板              执行程序
```

Linux 容器共享运行它们的 Linux 内核，不会各自启动一个内核。Ubuntu 镜像包含 Ubuntu 的用户空间文件，不等于一台完整的 Ubuntu 虚拟机。

源码常用的绑定挂载与 Volume 是两种不同的存储方式，第 4 节会对比它们。

## 3. 镜像与容器：模板和实例

同一个镜像可以创建多个容器。默认情况下，每个容器的文件修改相互独立，也不会修改原镜像。

假设原镜像已安装 `g++`、尚未安装 `cmake`。用它创建容器 A 和 B，然后只在 A 中安装 `cmake`，安装位置没有挂载外部存储：

| 操作或对象 | 是否有后来安装的 cmake |
|---|---|
| 原镜像 | 没有，容器内的修改不会自动写回镜像 |
| 容器 B | 没有，A 的修改不会自动同步到 B |
| 停止 A，再用 `docker start` 启动 A | 有，仍是同一个容器，可写层保留 |
| 删除 A，再用 `docker run` 从原镜像创建新容器 | 没有，新容器不继承 A 的可写层 |

**停止容器不等于删除容器。** 容器的可写层可以跨越停止和启动，但不能跨越删除和重建。

`docker run` 每次创建新容器，`docker start` 启动已有容器。使用 `--rm` 创建的容器会在退出后自动删除，不能再启动它。

如果希望以后创建的容器都自带 `g++` 和 `cmake`，应将安装步骤写进 Dockerfile，构建新镜像，再用新镜像创建容器。

## 4. 数据保存：Volume 与绑定挂载

判断数据是否会保留，先看它实际存在哪里：

| 方式 | 数据位置 | 删除容器后 | 常见用途 |
|---|---|---|---|
| 容器可写层 | 容器自身 | 随容器删除 | 临时文件 |
| Bind mount（绑定挂载） | 你指定的宿主机目录 | 宿主机文件保留 | 项目源码、配置文件 |
| Named volume（命名数据卷） | Docker 管理的存储位置 | 卷保留，除非同时或另外显式删除 | 数据库等应用数据 |

`docker run` 的 `-v` 参数可以指定绑定挂载或数据卷，区别在冒号左侧：

```text
-v "$(pwd)/test_data:/data"  → 宿主机绝对路径：绑定挂载
-v study_data:/data         → 卷名：命名数据卷
```

指南使用的是第一种。`$(pwd)` 表示当前目录，引号避免路径包含空格时被拆成多个参数。需要长期保存的数据，应放在容器可写层之外。

### 绑定挂载不是复制文件

```text
宿主机                         容器
~/cpp-demo/ ──绑定挂载──→ /workspace/
  └── main.cpp                  使用 g++ 编译
```

这里两条路径访问的是同一份文件。默认可读写挂载下，且文件权限允许时：

- 两边的修改都会反映到同一份文件上；程序是否自动加载修改，取决于程序本身。
- 删除容器，宿主机上的文件仍然保留。
- 在容器内主动删除挂载目录中的文件，也会删除宿主机上的对应文件。因此，绑定挂载不是备份。

只需要容器读取文件时，可以在挂载参数末尾加 `:ro`。如果编译产物要写入挂载目录，该目录需要可写。

### 判断文件是否保留

假设将宿主机的 `~/cpp-demo` 绑定挂载到容器的 `/workspace`，然后在容器中创建两个文件。删除容器后的预期结果如下：

| 文件 | 删除容器后的结果 | 原因 |
|---|---|---|
| `/workspace/hello.cpp` | 保留 | 实际保存在宿主机的挂载目录中 |
| `/tmp/notes.txt` | 删除 | 假设 `/tmp` 未挂载，文件只保存在容器可写层中 |

数据卷也有匿名形式，例如 `-v /data`，由 Docker 生成卷名。匿名卷通常也会保留，但使用 `docker run --rm` 时，匿名卷会随容器退出自动删除，命名卷不会。详见 [Volume 与绑定挂载](05-docker-volumes-and-bind-mounts.md) 和 [Docker 官方数据卷说明](https://docs.docker.com/engine/storage/volumes/#remove-anonymous-volumes)。

## 5. 端口映射：从宿主机访问容器服务

在默认桥接网络下，容器有自己的网络环境。服务监听容器的 `80` 端口，不代表它也在宿主机的 `80` 端口提供服务。本节示例以 Docker 在本机运行、容器使用桥接网络为前提。

`docker run` 的端口映射参数：

```text
-p 8080:80
   宿主机端口:容器端口
```

访问路径：

```text
宿主机浏览器访问 http://localhost:8080
                  ↓
           宿主机端口 8080
                  ↓
             容器端口 80
                  ↓
                Web 服务
```

端口映射不会改变程序监听的端口，也不会启动服务。服务仍需监听容器内的 `80`，Docker 负责转发。

`-p 8080:80` 默认发布到宿主机所有网络接口；如果只需要本机访问，可写为 `-p 127.0.0.1:8080:80`。详见 [端口映射](04-docker-port-mapping.md) 和 [Docker 官方端口发布说明](https://docs.docker.com/engine/network/port-publishing/#publishing-ports)。

如果容器仅用于编译 C++，没有需要从外部访问的网络服务，通常不需要端口映射。

### 两个容器能否使用相同端口？

两个桥接网络容器各有自己的网络环境，都可以监听自己的 `80` 端口：

| 容器 | 映射参数 | 在宿主机浏览器中的访问地址 |
|---|---|---|
| A | `-p 8080:80` | `http://localhost:8080` |
| B | `-p 8081:80` | `http://localhost:8081` |

它们不会冲突：容器端口属于各自的网络环境，宿主机端口也不同。在相同宿主机绑定地址和协议下，两个同时运行的容器不能占用同一个宿主机端口。这里的 `localhost` 指运行浏览器的本机。

## 6. 串起 C++ 开发场景

```text
Dockerfile：写明安装 g++、cmake
    ↓ 构建
镜像：包含开发工具的环境模板
    ↓ 创建并启动
容器：运行编译命令
    ↑ 绑定挂载
宿主机源码目录：保存和编辑代码
```

本仓库的 [phase9-cpp-dev](../phase9-cpp-dev/) 就采用这种方式：

| 文件或配置 | 对应职责 |
|---|---|
| [Dockerfile](../phase9-cpp-dev/Dockerfile) | 安装 `g++`、`cmake` 和 `make`，准备工具链镜像 |
| [compose.yaml](../phase9-cpp-dev/compose.yaml) 中的 `.:/workspace` | 将项目目录绑定挂载到容器 |
| `dev` 服务的 `command` | 配置 CMake、编译项目，再运行程序 |

修改挂载的源码后，重新执行编译即可；修改 Dockerfile 中的工具或依赖后，需要重建镜像，再用新镜像创建容器。完整实验见 [C++、CMake 与 Docker 开发环境](10-cpp-docker-development.md)。

本节要记住：

1. 镜像是模板，容器是实例。
2. 修改容器不会自动修改镜像。
3. 停止容器保留可写层，删除容器会删除可写层。
4. 重要数据通过数据卷或绑定挂载保存在容器可写层之外。
5. 端口映射顺序是“宿主机端口:容器端口”。
